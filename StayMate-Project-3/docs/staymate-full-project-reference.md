## 1. Что такое StayAI

SaaS-продукт: ИИ-консьерж для отелей и апартаментов (гость пишет боту → ИИ отвечает про наличие номеров, помогает забронировать, эскалирует сложные случаи живому админу). Целевой рынок — весь мир, но первые клиенты, скорее всего, украинские.

**Тарифы (заявлены на сайте):**
- Старт — €100/мес
- Профі — €200/мес (автобронирование + оплата)
- Мережа — €300/мес (unlimited / интеграция с PMS)

**Модель денег:** два независимых потока —
(А) отель платит StayAI подписку;
(Б) гость платит отелю за проживание через бота.

## 2. Архитектура — из чего состоит продукт

### 2.1 Маркетинговый сайт
- 11 HTML-страниц (uk/ru/en), живёт на **https://stayai.online**
- Задеплоен вручную через **Netlify Drop** (НЕ подключён к GitHub — это важно для будущих обновлений, см. раздел 6).
- Страницы: index, features, pricing, how-it-works, instructions, contacts + новый раздел **/cabinet/**.
- Есть старые незаконченные страницы-заглушки: `register.html`, `login.html`, `account.html`, `connect.html` — у них в `supabase-config.js` стоят плейсхолдеры (`PASTE_YOUR_SUPABASE_URL_HERE`), они **не рабочие** и не связаны с новым кабинетом. Решение об их судьбе (удалить/доработать) пока не принято.

### 2.2 Личный кабинет отеля (`/cabinet/`)
- Один HTML-файл, простой HTML/JS без сборки, использует Supabase JS через CDN.
- Функционал: регистрация/вход (Supabase Auth) → создание профиля отеля (генерирует уникальный `property_id`) → таблица номеров (тип/цена/вместимость/описание, кнопка "Зберегти номери" полностью перезаписывает список) → подключение Telegram-бота (вставляешь токен от @BotFather → кабинет сам регистрирует webhook и сохраняет данные).
- **Важный пробел:** нет полей для реквизитов оплаты отеля (актуально, когда будем подключать Fondy Split).

### 2.3 Backend-сервер ("мозг" ИИ-администратора)
- Node.js, хостится на **Railway** (проект `extraordinary-commitment`, сервис `staymate-concierge`, окружение `production`).
- Публичный домен: **staymate-concierge-production.up.railway.app**
- GitHub-репозиторий: `chernikovdanila2000-tech/staymate-concierge`, рабочая папка (Root Directory в Railway) — `staymate-concierge-brain`. Ветка `main`, автодеплой при пуше включён.
- Модель: `claude-sonnet-5`.
- Файлы: `server.js`, `tools.js`, `claude-client.js`, `telegram.js`, `system-prompt.js`, `package.json`, `.env.example`, `properties-setup.sql`, `supabase-setup.sql` (старый).

**Мультитенантная логика (актуальная версия):**
- Вебхук: `POST /webhook/telegram/<property_id>` — сервер по `property_id` из URL достаёт из Supabase название отеля и токен бота, ведёт диалог именно с его данными.
- Также есть: `POST /chat` (тестовый роут, требует `propertyId` в теле), `POST /webhook/wayforpay` (подтверждение оплаты), `GET /health`.
- История переписки хранится **в памяти процесса** (`Map`), НЕ сохраняется в базу — теряется при перезапуске сервера. Это известный технический долг, для продакшена нужно перенести в Supabase.
- Данные отеля кэшируются на 60 секунд, чтобы не дёргать Supabase на каждое сообщение.

**tools.js** — экспортирует `toolDefinitions` (единая схема для Claude) + `createTools(propertyId)` — фабрика, привязывающая функции к конкретному отелю:
- `check_availability` — ищет номера в таблице `rooms` по `property_id` и вместимости. **НЕ проверяет занятость по датам** (см. раздел 5, пробел №1).
- `create_booking` — находит номер, генерирует ID брони (`BK` + 6 символов, без дефиса), считает ночи и сумму, создаёт счёт на оплату через WayForPay, сохраняет бронь в `bookings` со статусом `pending_payment`.
- `escalate_to_human` — логирует и сохраняет в таблицу `escalations`.

**Оплата (WayForPay, Create Invoice API):**
- Сейчас используется **ПУБЛИЧНЫЙ ТЕСТОВЫЙ аккаунт** WayForPay (`test_merch_n1`) — свой реальный мерчант-аккаунт ещё не заведён.
- Модель простая: деньги от ВСЕХ гостей идут на **один** аккаунт (твой/StayAI), дальше нужно вручную переводить каждому отелю. Это осознанный временный компромисс.
- `.env` переменные: `WAYFORPAY_MERCHANT_ACCOUNT`, `WAYFORPAY_MERCHANT_SECRET`, `WAYFORPAY_DOMAIN`.

**Полный список переменных окружения на Railway:**
```
ANTHROPIC_API_KEY
SUPABASE_URL
SUPABASE_KEY          (service_role секретный ключ, НЕ anon!)
WAYFORPAY_MERCHANT_ACCOUNT
WAYFORPAY_MERCHANT_SECRET
WAYFORPAY_DOMAIN
API_BASE_URL           = https://staymate-concierge-production.up.railway.app
PORT
```
Старые `PROPERTY_ID` / `PROPERTY_NAME` / `TELEGRAM_BOT_TOKEN` больше не используются кодом (были нужны для одно-отельной версии), можно оставить — не мешают.

### 2.4 База данных (Supabase)
- Проект **StayAI**, URL: `https://nyknlyufbwjodbpyehtv.supabase.co`
- Таблицы:
  - **properties** — `property_id` (text, PK), `owner_id` (uuid → auth.users), `hotel_name`, `address`, `telegram_bot_token`, `webhook_connected`, `subscription_status` (default `trial`), `created_at`. RLS включён — владелец видит/редактирует только свою запись.
  - **rooms** — `id`, `property_id`, `room_type`, `price_per_night`, `capacity`, `description`, `created_at`. RLS — владелец управляет только своими номерами.
  - **bookings** — `id`, `booking_id` (уникальный), `property_id`, `room_type`, `check_in`, `check_out`, `guest_name`, `guest_contact`, `price_per_night`, `status` (`pending_payment`/`paid`), `payment_link`, `created_at`. RLS — только просмотр своих.
  - **escalations** — `id`, `property_id`, `reason`, `urgency`, `status`, `created_at`. RLS — только просмотр своих.
- Авторизация: Supabase Auth (email + пароль) для входа в кабинет.
- В таблице `rooms` остались тестовые данные под `property_id = 'panorama-apart-hotel'` (5 вымышленных номеров) — без связанной записи в `properties` (создавались до появления этой таблицы).
- Реальный тест через кабинет: отель **"Апартель"**, `property_id` вида `апартель-n82c`, номер "бизнес" (1430 грн, вместимость 2 — изначально была ошибочно сохранена как 1, исправлена).

## 3. Что реально работает (проверено сегодня, end-to-end)

Полный путь протестирован и подтверждён:
**Регистрация в кабинете → создание профиля отеля → добавление номеров → подключение своего Telegram-бота через @BotFather → гость пишет боту → сервер по property_id из URL находит нужный отель → Claude проверяет номера именно этого отеля в Supabase → создаётся бронь → генерируется ссылка на оплату (пока тестовый WayForPay).**

Всё это происходит **без ручного участия разработчика** — отель сам всё настраивает через кабинет.

## 4. История решений по оплате (чтобы не переигрывать заново)

1. Начинали со **Stripe** — оказалось, Stripe не поддерживает украинские юрлица для получения выплат → отказались.
2. Рассматривали **Stripe Connect** (сплит-платежи) — та же проблема с Украиной, подошло бы только для отелей вне Украины/СНГ.
3. Изучили украинские альтернативы:
   - **LiqPay** — проще, но верификация часто зависает, нет подтверждённого сплит-функционала.
   - **WayForPay** — ~2.2% комиссии, хорошо работает и с зарубежными картами, нет подтверждённого сплита, зато есть публичный тестовый доступ без регистрации.
   - **Fondy** — нашли официальный **Split Payments API** (через систему СЕП НБУ) — именно то, что нужно: гость платит один раз, деньги автоматически расщепляются между StayAI (комиссия) и отелем (по его банковским реквизитам — IBAN/ОКПО/название компании, отдельный аккаунт в Fondy отелю НЕ нужен).
4. **Сейчас в коде:** простая схема на WayForPay (один аккаунт на всех, деньги вручную пересылаются отелям).
5. **Цель на будущее:** Fondy Split — заблокировано багом на их стороне (см. раздел 5).
6. Также обсуждали и **отклонили** идею вообще убрать оплату из бота ("оплата при заезде") — отклонили, потому что тариф "Профі" на сайте явно обещает "автобронирование і оплата".

## 6. Важные технические уроки (чтобы не наступать на те же грабли)

- **Загрузка файлов на GitHub:** всегда открывать папку и выделять файлы ВНУТРИ неё (Cmd+A), а не перетаскивать саму папку — иначе GitHub создаёт лишнюю вложенную подпапку, и Railway перестаёт находить `package.json`.
- **Кнопка "Redeploy" в Railway НЕ подтягивает код заново с GitHub** — она просто перезапускает уже собранный образ. Чтобы точно обновить код, нужен новый коммит (даже тривиальная правка) — тогда сработает автодеплой.
- **Как проверить, какой код реально работает в контейнере:** Railway → вкладка Console → команда вида `grep НУЖНАЯ_СТРОКА file.js`.
- **Netlify:** сайт задеплоен вручную (Drag & Drop), НЕ подключён к Git. Чтобы обновить — нужно перетаскивать **всю** папку сайта целиком (не отдельные файлы), иначе остальные страницы удалятся. Зона для перетаскивания часто невидима, пока не начнёшь реально тащить файл над окном браузера. Если "Access denied" — пробовать Chrome вместо Safari.
- **SUPABASE_KEY на сервере** — должен быть `service_role` (секретный), НЕ `anon`/`publishable` — иначе сервер не сможет писать в базу.
