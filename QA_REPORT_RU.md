## 3. Найденные баги — все исправлены

### Баг №1 (вероятная причина "сайт лёг после деплоя") — критичный
**Регистрация уводила пользователя на жёстко прописанный `https://stayai.online/` вместо текущего сайта.**

В коде кабинета после успешной регистрации был хардкод:
```js
window.location.href = SITE_ORIGIN + '/'; // SITE_ORIGIN = 'https://stayai.online'
```
Если сайт открыт не по адресу stayai.online (например, по адресу netlify.app, превью-деплой или другой момент, когда домен ещё не до конца настроен) — человека после регистрации выкидывало на другой домен, который может быть недоступен или выглядеть "сломанным". Это ровно то поведение, которое выглядит как "сайт лёг" сразу после того, как кто-то зарегистрировался.

**Исправлено:** теперь используется `window.location.origin` — текущий адрес сайта, каким бы он ни был, а не всегда stayai.online. Есть автотест-регрессия (`auth.spec.js`), который теперь проверяет, что после регистрации адрес не меняется на посторонний домен.

### Баг №2 — средний, реальный визуальный/UX баг
**Декоративный 3D-фон на главной странице (index.html) создавал невидимую горизонтальную прокрутку на 234–768px на всех размерах экрана**, включая обычный desktop. `clip-path` в CSS визуально обрезает фон, но не мешает браузеру считать его частью общей ширины страницы — из-за этого появлялась невидимая полоса прокрутки вправо, и на телефоне/тачпаде страницу можно было "смахнуть" в пустоту.

**Исправлено:** добавлен `overflow:hidden` в контейнер фона + защитный `overflow-x:hidden` на `html`/`body` на всех страницах и в кабинете, чтобы такой класс багов не повторился где-то ещё.

### Баг №3 — мелкий, accessibility
**Цифры шагов (01, 02, 03, 04) на странице "Инструкция" были почти нечитаемы** — контраст текста к фону 1.57:1 вместо минимально требуемых 4.5:1 (использовался цвет, предназначенный для тонких линий-разделителей, а не для текста).

**Исправлено:** цвет заменён на тот, что уже используется для обычного читаемого текста сайта. Проверено автоматическим a11y-аудитом (axe-core) — теперь 0 критичных/серьёзных нарушений на всех проверенных страницах.

### Баг №4 — мелкий, но реальный
**Кнопка входа/регистрации в кабинете не блокировалась во время запроса** — при быстром двойном клике (или нетерпеливом повторном клике, пока идёт запрос) могло уйти два запроса на вход/регистрацию одновременно.

**Исправлено:** кнопка теперь отключается на время запроса и включается обратно после ответа (успех или ошибка).

## 4. Что осталось (не баги, а зафиксированные ограничения)

- **Глубокая часть кабинета (номера, каналы связи) — только украинский язык.** Об этом было явно сказано пользователю заранее (отдельная, более крупная задача), это не забытая ошибка.
- **Автопродление подписки через WayForPay** (регулярные платежи) — построено на данных из открытых источников, точные названия полей API не сверены с живой документацией WayForPay (нет доступа к их вики из этой среды). Требует тестирования в песочнице WayForPay перед реальными деньгами — подробности в `staymate-concierge-brain/README.md`.
- Цветовой контраст проверен только автоматически (axe-core) — это ловит однозначные нарушения WCAG, но не заменяет ручную проверку дизайнером на реальных экранах при разном освещении.

## 5. Console / network ошибки

На всех проверенных страницах и сценариях (главная, регистрация, вход, неверный пароль, дашборд) — **0 ошибок в консоли, 0 необработанных исключений, 0 битых изображений**, кроме заведомо известных: в этой тестовой песочнице заблокирован доступ к Google Fonts и CDN (сеть намеренно ограничена окружением, где я работаю) — это не относится к реальному сайту пользователей, там шрифты и CDN загружаются нормально, я это явно отфильтровал в тестах и в отчёте.

## 6. Security — что проверено

- Кабинет никогда не показывает данные готеля/дашборд без действующей сессии — ни при обычном заходе, ни в свежем браузере, ни после выхода из аккаунта.
- Во frontend-файлах нет секретов (service_role ключ Supabase, ключ Anthropic, реальный секрет WayForPay) — только публичный (anon/publishable) ключ Supabase, как и должно быть.
- Во всех SQL-миграциях для многопользовательских таблиц (properties, rooms, bookings, channels, conversations, subscription_orders) явно включён Row Level Security.
- В коде кабинета нет ни одного места, где ID отеля/пользователя брался бы из URL — доступ к данным всегда идёт через `owner_id = текущий залогиненный пользователь`, поэтому подменить ID в адресной строке и получить чужие данные архитектурно невозможно.

**Что нельзя проверить автоматически (честно):** настоящую изоляцию данных между разными готелями (tenant isolation) на уровне базы данных — для этого нужен живой доступ к продакшен-Supabase с двумя реальными аккаунтами, тестировать такое против реальной базы в автоматическом прогоне небезопасно и не входило в объём этой сессии. Судя по коду — весь доступ идёт через RLS-политики и `owner_id`, но финальное подтверждение может дать только ручная проверка с двумя реальными аккаунтами в самом Supabase.

## 7. Что физически нельзя проверить из этой среды

- Реальный деплой на Netlify (у меня нет доступа посмотреть на живой сайт stayai.online) — все тесты идут против локальной копии тех же файлов через локальный сервер.
- Реальная отправка email (Supabase/Resend) — сеть до этих сервисов заблокирована в этой среде, поведение писем проверялось только на уровне кода (какая функция дергается, какой текст).
- Платежи WayForPay по-настоящему — тестовый мерчант-аккаунт, реальные деньги проверить нельзя и не нужно.
